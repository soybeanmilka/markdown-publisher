# 多平台投稿：官方 API 可行性核查

核查日期：2026-09-24。只采用平台自身的开放平台、开发者文档或官方客服说明。这里的“可用”指普通个人创作者能按官方流程接入；不把抓取网页接口、保存 Cookie 或模拟登录当成可维护的发布 API。

| 平台 | 官方自动发布能力 | 个人作者的实际可行性 | 插件应采取的做法 |
| --- | --- | --- | --- |
| 微信公众号 | **可创建图文草稿并可通过发布接口提交发布**。 | **普通个人主体账号自 2025-07 起不具备这些发布接口权限**；通常需要已认证且符合权限范围的企业公众号。 | 对个人号降级为“生成 HTML/素材包 + 打开后台”；仅合格账号开放本机后端的草稿/发布连接器。 |
| 小红书 | 未找到面向普通创作者的“发布笔记”公开 API。官方公开站点目前展示的是商家/商品等业务 API。 | **不可作为通用自动发布承诺**。如有机构合作权限，应以其书面/API 文档为准。 | 生成笔记正文、标题、标签和图片清单，并打开创作页供手动提交。 |
| 知乎 | 当前开放平台提供数据检索、用户内容读取及“我的创作”数据能力；公开目录未列出创建/发布回答或文章的写入接口。 | **不能用公开 API 自动发文**；即便申请到 Access Secret，也只应调用获准的数据接口。 | 生成知乎适配 Markdown，保留人工粘贴、预览和发布。 |
| Bilibili | **可通过开放平台投递视频稿件**，也有“唤起客户端投稿并预填”的能力。 | 可行但不是零配置：先完成身份认证、创建应用、申请 `ARC_BASE`，再由用户 OAuth 授权；权限申请/审核是前置条件。公开资料只证明视频稿件，不代表专栏文章可自动发。 | 第一阶段做 B 站视频投稿连接器（上传/封面/提交或唤起客户端）；文字学习笔记则生成视频脚本和投稿元数据。 |
| CSDN | 未找到面向普通博客作者的官方公开发文 API。官方客服说明的发布路径是登录后进入 PC/APP 创作中心。 | **不能承诺 API 自动发文**。 | 继续输出 CSDN Markdown；可提供“打开创作中心 + 粘贴检查清单”。 |

## 平台依据与边界

### 微信公众号：支持草稿与发布，产品上仍应保留确认点

- 公众号服务端 API 的[新增草稿接口](https://developers.weixin.qq.com/doc/service/api/draftbox/draftmanage/api_draft_add)创建草稿并返回 `media_id`；[提交发布接口](https://developers.weixin.qq.com/doc/service/api/public/api_freepublish_submit)以它提交发布，随后以[发布状态查询接口](https://developers.weixin.qq.com/doc/service/api/public/api_freepublish_get)查询异步结果。提交成功不等于最终发布成功，仍可能审核失败。
- [发布能力说明](https://developers.weixin.qq.com/doc/service/guide/product/publish.html)明确：自 2025-07 起，个人主体账号、未认证企业主体账号及不支持认证账号的相关接口权限会被回收；普通公众号的适用范围也以认证条件区分。因此不能对个人订阅号承诺自动发布。
- 正文入参为 HTML，外链图片会被过滤，需先用图文图片上传接口取得可用 URL；封面还需要永久素材的 `thumb_media_id`。官方[接口配额页](https://developers.weixin.qq.com/doc/service/guide/dev/api/limit.html)列出草稿新建、提交发布及状态查询的日配额。
- 这些是服务端 API，不能在插件网页/前端直接调用；AppSecret 必须只由本机受控后端或自建服务保存，不得写入笔记、仓库或前端配置。产品上仍应把发布做成一个显式确认动作。

### 小红书：公开开放平台不等于笔记创作开放平台

- [小红书开放平台 API 文档](https://open.xiaohongshu.com/document/api)公开的示例属于商品类目等商家能力。核查到的官方公开目录中没有可供普通个人创作者调用的“创建/发布笔记”端点。
- 这只能得出“不能基于公开文档实现通用发布器”，不能推出平台绝对不存在定向合作接口。若用户拿到合作方文档和应用权限，再单独评审接入。

### 知乎：当前是数据 API，不是投稿 API

- [知乎数据开放平台](https://developer.zhihu.com/)把能力列为搜索、热榜、用户数据、我的创作全文/评论/数据等；其[Bearer 鉴权说明](https://developer.zhihu.com/)写明 Access Secret 从个人中心取得，且申请访问权限需要联系开放平台、说明场景与调用量。
- 在该官方目录中未见“新建文章”“发布文章”“提交回答”写接口。因此不应把其数据 API 误接成内容发布 API，也不应以浏览器自动化替代官方授权。

### Bilibili：视频分发可接入，但要应用审核和用户授权

- [开放平台身份认证说明](https://open.bilibili.com/doc/4/8673959e-f7bb-56e6-6e68-d225f971b81b)明确：身份信息审核通过后才能创建应用并拥有稿件分发等能力。
- Bilibili 开放平台发布的[账号授权文档](https://bilibili.apifox.cn/doc-7492454)说明接入前须申请应用，取得 `client_id`/`secret`，并通过 OAuth 2.0 由用户授权换取 `access_token`。
- 官方[视频稿件删除接口](https://open.bilibili.com/doc/4/23d78390-4119-1e5f-2bbe-b45bd5cecdb0)标为 `ARC_BASE`、需要申请权限和用户授权；同一官方文档中心的[投稿唤起接口](https://open.bilibili.com/doc/4/08f935c5-29f1-e646-85a3-0b11c2830558)说明可预填客户端投稿内容。这证明“视频稿件分发”是一条正当接入路径，但具体上传/提交接口、资质和限额应以获批后的最新文档为准。

### CSDN：官方支持 Markdown 编辑，但未公开作者发文 API

- CSDN 官方博客公告称 [Markdown 编辑器已上线/改版](https://blog.csdn.net/blogdevteam)，适合本工具继续生成其兼容 Markdown。
- 官方客服的[发文指引](https://ask.csdn.net/questions/7916874)要求登录后在 PC 创作中心选择“文章”或在 App 选择“写文章”。核查到的官方公开信息没有相应的作者发文 API 文档。

## 落地结论

第一版插件应把“多平台发布”拆成两类：

1. **条件化官方 API 连接器**：Bilibili 视频投稿（待权限获批后启用）；微信公众号仅在账号已认证且具备发布权限时启用。个人主体公众号应默认走手动后台发布。每次发布均让用户看见目标账号、标题和最终确认步骤。
2. **安全的半自动投稿包**：小红书、知乎、CSDN 输出平台适配正文、标题/摘要/标签/封面建议，并一键打开对应创作中心。这样已消除重复格式整理，又不依赖未授权接口或高风险模拟登录。

后续若增加任何账号接入，凭据必须放在本机忽略文件或系统凭据库；不得写入 Obsidian 笔记库、插件配置示例或 Git 仓库。
